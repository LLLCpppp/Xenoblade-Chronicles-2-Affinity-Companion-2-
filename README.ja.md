# ゼノブレイド2 キズナリング助手

[中文](README.md) · [English](README.en.md)

『ゼノブレイド2』のキズナリング進捗とユニークモンスター討伐を管理する、ローカルで使えるツールです。推奨リポジトリ名：**`xc2-affinity-companion`**。

- ライコの雷制御の特訓4ノードとホタルのスチールハート3ノードは手動進行とし、残り30個の通常会話ノードは傭兵団で進行可能とします。どちらの確定ルールも旧個人判定より優先します。

## 起動

解凍したフォルダーの **`index.html`** をブラウザーで開いてください。インストール・ビルド・アカウントは不要です。Python がある場合は、プロジェクト内で `python -m http.server 8000 --bind 127.0.0.1` を実行し、[localhost:8000](http://127.0.0.1:8000) からも利用できます。

- 通常の会話回数条件はプレイヤーの確認に基づき傭兵団で進行可能とし、旧個人判定より優先します。キズナトーク・指定のストーリーNPC・クエストなどの独立した条件は元の判定を維持します。
- 現在の段階で進行できず、次の段階の解放条件が信頼度以外の場合は「手動での進行が必要」と表示します。信頼度の場合は従来の案内を維持し、原条件や傭兵団の判定は変更しません。

## 主な機能

- 中国語・英語・日本語の切り替えと、3言語でのブレイド・敵・ノード・地域検索。
- ブレイド選択欄は初期状態で開き、追加後も開いたまま。未登録・確認待ち（琥珀色）・確認済み（緑色）の順に表示。画像を選ぶとリングへスクロールします。5段階のキズナリング図、分岐ごとの進捗入力、取り消しに対応。
- **すべて達成にする**：現在のブレイドの全5段階・全スキルノードを達成済みにし、討伐も同期。取り消し可能です。
- 各分岐の直後のノードのみを対象とする傭兵団の進行判定。手動の前提条件は飛ばしません。
- 派遣可能カードに「傭兵で進行：N（信頼度 M）」を表示。信頼度は対象スキルノードの内数で、段階解放は除外し、並べ替え項目は追加しません。手動・要確認・指定任務条件で分岐の集計を止め、段階の鍵は含めません。1回の任務での達成を保証しません。
- 達成ノード数・達成率で並べ替え、カードをグリッド表示して現在の順位を付けます。段階の鍵はノード数に含めません。進捗分類は重複可能です。
- 未達成討伐とリングの相互同期。同じ敵を必要とする他のブレイド・到達状況・リングへのリンクを表示。
- クビラは通常・覚醒の片方のみ登録可能。
- ブラウザー内への保存、JSON の入出力、保存済みの個人判定。プレイヤーデータの送信機能はありません。
- **全ブレイドをリセット**：警告画面で確認後、登録・リング進捗・討伐チェック・形態バックアップ・取り消し履歴を消去して未登録に戻します。個人判定は保持します。必要なら先にバックアップをエクスポートしてください。

## データ・訳名

取得日：**2026-11-08**。登録可能な55ブレイド、493分岐、2,188スキルノード、220段階条件を収録。討伐表は30ブレイドの82ノードで、確認済みユニーク名50件、未確定の敵名3件、敵名の指定がない条件3件を含みます。

条件・画像・リンクは [楽園データ管理室](https://xenoblade2.cn/异刃)、基本の除外ルールは [傭兵団任務ページ](https://xenoblade2.cn/佣兵团任务) が出典です。英語・日本語名は Wiki の記載を優先し、補助資料として [Xenoblade Data](https://xenoblade.github.io/) の同じテーブル・同じ行番号を照合しています。対応が確認できない名称や説明文は本プロジェクトの翻訳です。`locales.json` と [ATTRIBUTION.md](ATTRIBUTION.md) に出典を記載しています。

中国語 Wiki 原文を優先し、リングの詳細から原文を展開できます。照合レポート・CSV・元データは中国語のままです。言語切り替えで保存用の識別子や Wiki リンクは変更しません。

## 保存データの移行

別ブラウザー・別ドメイン・別のファイル位置・GitHub Pages に移る前に進捗をエクスポートし、移行先でインポートしてください。個人判定はバックアップに含まれ、公開リポジトリには私的なプレイヤー記録を同梱しません。未読込の個人判定を、傭兵で進行可能と決めつけることはありません。

このツールは記録用です。ゲームのセーブデータは変更しません。

## 開発・GitHub

プロジェクト内で `node tests/check.cjs` を実行すると、データ・判定・保存・翻訳の整合性を検査できます。`python scripts/build_standalone.py` で単一HTML版を `dist/` に生成できます。

アップロードは [手順書（中国語）](docs/GITHUB_UPLOAD.zh-CN.md) または [GitHub 公式ガイド](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github) を参照してください。GitHub Pages は `main` ブランチの `/ (root)` を指定できます。

非公式のファンツールです。第三者のゲーム文章・画像の権利は各権利者に帰属します。コードのライセンスは未選択です。詳しくは [出典](ATTRIBUTION.md) を参照してください。

### PC上のファイルに保存

ページ上部のローカル進捗ファイルからJSONに自動保存できます（File System Access対応のChrome / Edgeなどが必要です）。初回はファイルを新規作成して関連付け、保存先を選んでください。保存完了を確認してからページを閉じ、次回は同じ進捗ファイルを開いて続けてください。リング・討伐チェック・個人判定・形態バックアップを保存します。

関連付けを解除すると以降の書き込みを停止し、ブラウザーのキャッシュは保持します。ファイルが外部で変更された場合は開き直すまで自動保存を停止します。非対応ブラウザーでは従来のエクスポート・インポートを利用できます。ファイル読み込みは全進捗を置換し、従来のインポートは引き続き結合します。
